# Staging environment

Staging is a complete, separate copy of the system with its own database,
private bucket and test users. Production data is never used for development,
automated tests or seed scripts.

## 1. MongoDB Atlas staging cluster

1. Atlas → top-left project menu → **New Project** → name `Expresso Portal – Staging`.
   (A separate project keeps users, IP rules and alerts separate from production.)
2. **Create cluster** → *Free (M0)* or *Flex* is enough. Provider/region: the same
   region family as production.
3. **Database Access** → Add new database user
   - Username `expresso_staging_app`, autogenerated password (save it).
   - Database user privileges → *Specific privileges* → `readWrite` on database `expresso_staging`.
4. **Network Access** → Add IP address → *Add current IP address* (your Mac).
   Add the staging API host's outbound IP later if staging is deployed. Avoid `0.0.0.0/0`.
5. **Connect → Drivers** → copy the `mongodb+srv://…` string and add the database
   name: `mongodb+srv://expresso_staging_app:<password>@<cluster>.mongodb.net/expresso_staging?retryWrites=true&w=majority`

## 2. Point your Mac at staging (not production)

Edit `portal-api/.env` so it holds staging values only:

```
NODE_ENV=development
DB_ENVIRONMENT=staging
MONGO_URI=<staging connection string>
JWT_SECRET=<new random value — do not reuse production's>
FRONTEND_URL=http://localhost:3000
API_PUBLIC_URL=http://localhost:5050
AWS_REGION=<region>
AWS_S3_BUCKET=<staging public bucket, or leave empty to use local disk>
AWS_S3_PRIVATE_BUCKET=<staging private bucket, or leave empty to use local disk>
SMTP_HOST=… (optional on staging)
SUPER_ADMIN_EMAIL=<your staging admin email>
SUPER_ADMIN_PASSWORD=<staging-only password>
```

Production values live only on the production host (Render). Generate a secret with
`node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"`.

## 3. Seed staging

```
cd portal-api
node src/scripts/seedRoles.js
node src/scripts/seedUser.js
node src/scripts/seedProcurementCategories.js
node src/scripts/seedWebContent.js
node src/scripts/seedStagingFixtures.js     # test companies and one user per role (added with the validation step)
```

Scripts only run against a remote database when `DB_ENVIRONMENT=staging`; with
`DB_ENVIRONMENT=production` writing scripts refuse to run.
